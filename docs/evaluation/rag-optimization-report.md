# RAG 针对性优化报告

## 结论

已建立可重复的评测链路，并用真实 BGE/Chroma 执行了基线、开发集消融、候选对比与基线回放。本轮只实现了可配置词法融合权重和**评测专用术语扩展**。线上仍使用原混合检索默认参数，不启用扩展、不更换模型、不增加 Cross-Encoder 或二次检索。

总体指标的提升来自开发集，不能宣称已经提升泛化能力。主要缺陷是证据不足拒答，而不是完全无法召回同主题段落。生成质量本轮未实测，所有生成/Judge 数值为 null，不以检索指标冒充回答质量。

## 数据与实验纪律

40题、30可答、10无答案；开发集与留出集各15可答+5无答案。问题依据项目的16个政策章节构造，不是采集的真实客户日志；由开发助手逐条对照原文标注并保存证据，尚未经独立人工复审。所有结果来自实际运行，没有生成或补填分数。

在首次基线前冻结 `dataset-v1.json`，随后未修改 Ground Truth。只根据开发集选择候选，在 `selection-v1.json` 记录配置，再执行候选全量验证。报告已经展示留出集的失败题，后续如据这些题修改规则，它们便不能继续充当未见测试集，应另建盲测集。

基线使用 K=2、BGE中文模型、Chroma cosine、dense阈值0.50、lexical兜底0.30、词法系数1.0；每题检索3次，记录排名稳定性与所有耗时。索引初始化、热身和稳态检索耗时分开。使用 `.tmp/rag-evaluation-index`，不改写线上索引。

## 开发集消融与决策

| 配置 | Recall@K | MRR@K | nDCG@K | 标注 Context Relevance | 无答案检索拒答率 | P95 检索 ms |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 词法权重0.25 | 86.67% | 0.9333 | 0.9050 | 0.3500 | 20.00% | 10.73 |
| 术语扩展 | 93.33% | 1.0000 | 0.9716 | 0.3750 | 20.00% | 9.64 |
| 扩展+低词法权重 | 93.33% | 0.9667 | 0.9470 | 0.3750 | 20.00% | 10.15 |
| 阈值0.60 | 73.33% | 0.8000 | 0.7716 | 0.4000 | 20.00% | 9.93 |
| 阈值0.65 | 66.67% | 0.7333 | 0.7050 | 0.4000 | 60.00% | 9.01 |
| 阈值0.70 | 36.67% | 0.4000 | 0.3858 | 0.3000 | 80.00% | 9.60 |

- **降低词法权重**：开发集排序有改善，但与术语扩展组合反而弱于单独扩展；不合并堆叠。
- **术语扩展**：保留原问题，只追加如“验货→仓库验收/退款到账”“刻在→定制商品”的词汇。不查询题号或标准答案、不调用模型。改善了开发集口语表达失配，作为候选保留。
- **提高阈值**：0.60、0.65、0.70的可答误拒率分别为13.33%、20%、60%。0.70虽把开发集无答案拒答率提高到80%，却牺牲大量可答问题，拒绝采用。发票例中的词法0.375仍能绕过向量阈值；单改向量阈值不是充分性判断。
- **扩大候选池诊断**：现有Top-6配置在开发集Recall@6=96.67%，Context Relevance降为0.1547，拒答率仍20%。这是扩大上下文的消融，不是已实现Adaptive Retrieval，也不能与K=2直接作为同预算优化比较。K还决定dense候选数，因此扩大K可能改变融合首位排序。
- **Cross-Encoder**：未下载、未执行，不能声称其无效。当前知识库只有16个切片，召回与证据充分性问题混杂，先扩大盲测集并建立生成质量基线，再用独立重排器验证排序收益和资源成本。
- **Adaptive Retrieval**：未实现。没有可靠的缺失事实检测器时，二次检索容易返回更多同主题噪声；不凭Top-1相似度启动循环。

## 具体失败案例与原因

| 案例 | 实际现象 | 原因与边界 |
| --- | --- | --- |
| rag-005（dev）刻名字的杯子能退吗 | 基线先返回普通七天退款，扩展后特殊商品升首位 | 口语“刻在”未对齐“定制”，词法冲突放大排序误差 |
| rag-011（dev）退件要验货后才退钱吗 | 基线Top-2没有退款到账时效，扩展后召回 | “验货”与原文“仓库验收”表达差异 |
| rag-003 / rag-013（dev）多条件流程 | 主政策命中，但取消/工单审批章节未完整召回 | Top-2预算和跨章节覆盖不足；只看Hit会掩盖缺证据 |
| rag-031（dev）退货运费谁承担 | 返回七天退款章节，dense约0.6484 | 同主题不包含运费承担规则，不能靠主题相关度回答 |
| rag-033（dev）一年后开票流程 | 发票章节dense约0.7291、lexical0.375 | 高相似度不代表存在超出45天后的办理流程 |
| rag-016（test）签收但未收到能保证退款吗 | Top-2为七天退款、订单取消，漏物流异常 | 退款措辞干扰主要意图；留出集中仍未解决 |
| rag-030（test）物流工单重复提交 | 响应时效召回，工单幂等与确认章节遗漏 | 多章节覆盖不足 |
| rag-032/034/036/038（test）门店/领券/报价/备用机 | 返回相关主题章节，但均无所需事实 | 无答案拒答主要短板，不能据空缺自行补充政策 |

逐题完整来源、内容、chunk ID、dense/lexical排名与分数、最终排名见每个实验 `results.json`。机器生成的失败原因只是标签对照诊断，上表才是依据政策与轨迹进行的解释。

## 生成与引用质量：未测量，不推断

Answer Correctness、Faithfulness、Citation Support Rate、最终Abstention Accuracy及生成/Judge延迟本轮均为null。框架已实现可选生成和逐事实Judge；默认不调用任何LLM，包括本地Ollama。不使用路径存在率替代语义引用支持率。没有证据证明本轮检索候选提高了回答正确率或引用支持率。

同模型自评可能存在偏差；正式生成评测应优先使用不同Judge，并对盲抽样结果做独立人工校准。该模块只评估政策RAG回答，不等同于完整线上Agent工具决策成功率。

## 资源、复现与回放

本轮保持同一约94.8MB ONNX权重和2个Embedding线程，未新增模型；未测量进程峰值内存。P95约9ms的微小变化属于单机时间噪声，不宣称加速。`baseline-replay-v1` 在最终代码默认参数下复跑，所有检索质量指标与初始基线一致。模型文件SHA-256、依赖版本、源文件/锁文件/数据集哈希、系统信息均保存在报告元数据；耗时不保证跨机器一致。

实际运行命令与可选生成入口见 [评测框架说明](rag-evaluation.md)。实验数据目录为 [data/evaluation/rag](../../data/evaluation/rag/)，保留基线、候选、消融、回放与机器可读对比，不覆盖旧报告。

## 下一步

1. 对现有Ground Truth做独立人工复审，补充真实且去标识的客户问题，特别是同主题无答案、部分可答和多条件需求；建立未见过的盲测集。
2. 用独立Judge评估答案事实和引用，再分析“已有证据未用上”与“检索缺证据”各占多少。
3. 针对候选池已包含正确章节的失败，才做Cross-Encoder排序实验；针对缺少某个事实的请求，先定义证据充分性/部分拒答标准，再试一次有上限的补检索。
4. 设发布门槛：留出Recall/nDCG不降、无答案拒答不降、生成忠实性不降，并报告延迟与资源代价。当前候选未达到足以改变线上默认行为的证据门槛。
